# Design

Start with the user's task, the product's priorities, and the environments where the task happens. For feature discovery, use available feedback and usage evidence to identify the problem before surveying Apple capabilities.

Open the relevant live [HIG pattern](https://developer.apple.com/design/human-interface-guidelines/patterns) and [component guidance](https://developer.apple.com/design/human-interface-guidelines/components/). Compare native ways to complete the task, including hierarchy, navigation, actions, and input on each affected platform. Use [interface guidance](../references/interface.md) when the design needs to adapt.

Describe the proposed flow, which parts adapt, and what state stays continuous. Use framework documentation or a current Apple sample when the behavior of a candidate component affects the design. Carry the expected behavior into implementation and runtime verification.
